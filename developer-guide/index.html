    Key Design Patterns¶

    • FastAPI + Service Layer — Routers handle HTTP concerns (validation, file uploads, response formatting). Services contain all business logic and ML inference. Routers access services via request.app.state.<service>.
    • Lifespan Startup — All ML models are loaded once during application startup using FastAPI's lifespan context manager. This avoids cold-start delays on individual requests.
    • In-Memory Stores (POC) — Face database, webhook registry, consent records, analytics events, batch jobs, and workflow definitions all live in Python dictionaries/deques. In production, replace with Redis, PostgreSQL, or equivalent persistent stores.
    • Singleton Services — AMLScreeningService and AnalyticsService use the singleton pattern (__new__) to share state across the application.

    2. Getting Started¶

    Prerequisites¶

    Requirement Version
    Python 3.10+ (3.11 or 3.12 recommended)
    pip Latest
    System libraries libgl1, libglib2.0-0 (Linux only — for OpenCV)
    Disk space ~1 GB for ML models (auto-downloaded on first run)
    RAM ≥4 GB (models consume ~1–2 GB at runtime)

    Installation¶

    # 1. Clone the repository
git clone <repo-url> ekyc-poc
cd ekyc-poc

# 2. Create a virtual environment
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Run the server
uvicorn app.main:app --host 0.0.0.0 --port 8080

# 5. Verify it's running
curl http://localhost:8080/health
# → {"status": "ok"}

    First Startup¶

    On first run, models are auto-downloaded to the models/ directory:

    ⬇️  Downloading anti-spoof-mn3 model (~12MB)...
✅ Anti-spoof model saved
⬇️  Downloading deepfake detection model (~343MB)...
✅ Deepfake detection model saved
Loading ML models...
✅ PP-OCRv5 loaded
✅ Liveness: ML anti-spoof + MediaPipe + deepfake loaded
✅ Deepfake detection: ViT model loaded
All models loaded.

    InsightFace's buffalo_l models (~300 MB) are downloaded to ~/.insightface/models/buffalo_l/ automatically by the InsightFace library.

    Router → Service Pattern¶

    Every router follows the same pattern:

    # In router (e.g., app/routers/verification.py)
@router.post("/verify-face")
async def verify_face(request: Request, ...):
    service = request.app.state.face_service  # Access service from app state
    result = service.compare_faces(image1, image2)  # Delegate to service
    return result  # Return as JSON

    Services are instantiated once in main.py's lifespan() and stored on app.state.

    4. Core Services Deep Dive¶

    4.1 Face Verification (face_verification.py)¶

    What it does: 1:1 face comparison, multi-face detection, and 1:N face search against an in-memory database.

    Key algorithms: - InsightFace buffalo_l — ArcFace-based face recognition model providing 512-dimensional embeddings - Cosine similarity for face matching (threshold: 0.4) - Largest-face selection when multiple faces are present

    Capabilities: - compare_faces() — 1:1 match between two images - detect_faces() — Detect all faces with age, gender, bounding box - register_face() / search_face() — In-memory face database for 1:N search - detect_duplicate() — Check if a face already exists in the database

    Dependencies: insightface, onnxruntime, numpy, opencv-python-headless

    4.2 Liveness Detection (liveness.py)¶

    What it does: 6-layer presentation attack detection combining ML models and signal analysis.

    Layers and weights:

    Layer Weight Method
    ML Anti-Spoof 0.35 anti-spoof-mn3 (MobileNetV3, ONNX) — trained on CelebA-Spoof
    Deepfake 0.20 Deep-Fake-Detector-v2 (ViT-B16, ONNX)
    Context 0.20 Scene analysis — background consistency, lighting
    Depth 0.10 MediaPipe Face Landmarker — 478 landmarks with z-depth
    Texture 0.08 Pixel-level texture analysis (LBP, noise patterns)
    Color/Frequency 0.07 Moiré detection, color banding, FFT analysis

    Threshold: Combined score ≥ 0.45 = live

    Model auto-download: The anti-spoof model is downloaded from OpenVINO Model Zoo on first use. MediaPipe's Face Landmarker task file is also auto-downloaded.

    Dependencies: onnxruntime, mediapipe, opencv-python-headless, numpy

    4.3 Deepfake Detection (deepfake_detection.py)¶

    What it does: Classifies face images as real or deepfake using a Vision Transformer.

    Model: Deep-Fake-Detector-v2 (ViT-base-patch16-224), ONNX format (~343 MB) - Source: HuggingFace onnx-community/Deep-Fake-Detector-v2-Model-ONNX - Labels: {0: "Realism", 1: "Deepfake"} - Preprocessing: resize to 224×224, rescale to [0,1], normalize (mean=0.5, std=0.5)

    Face extraction: Uses Haar Cascade (haarcascade_frontalface_default.xml) for lightweight face cropping before classification.

    4.4 Document OCR (document_ocr.py + passport_ocr.py)¶

    What it does: Auto-detects document type (passport, ID card, driving license) and extracts structured fields.

    Processing pipeline: 1. Document type detection — Analyzes aspect ratio, MRZ presence, and text patterns 2. MRZ extraction (passports) — Multi-strategy via mrz_detector.py: - PassportEye direct detection - PaddleOCR text → MRZ reconstruction - Geometric crop + re-read 3. VIZ extraction — Regex-based field extraction from OCR text (names, dates, document numbers, CID for Bhutanese documents) 4. PaddleOCR PP-OCRv5 — Text extraction engine for non-MRZ regions

    Supported documents: - Passports (MRZ TD3 format) - National ID cards (including Bhutanese CID) - Driving licenses - Front + optional back page

    Dependencies: paddleocr, paddlepaddle, passporteye, opencv-python-headless

    4.5 Fraud Detection (fraud_detection.py)¶

    What it does: 4-check forensic analysis of document images.

    Check Weight Technique
    Fake Document 0.30 ELA (Error Level Analysis), EXIF validation, edge artifacts, colour consistency
    Photo Substitution 0.25 Compression analysis, lighting consistency, boundary artifacts
    Tampering 0.25 Font consistency, spacing analysis, field-level forensics
    Copy/Screen 0.20 Moiré pattern detection, colour distribution, DPI analysis

    Thresholds: Each check has an individual threshold (0.50–0.55). The overall fraud score is a weighted average; ≥ 0.55 = flagged as fraudulent.

    No ML models — Pure computer vision and statistical analysis.

    4.6 Security Features (security_features.py)¶

    What it does: Validates physical document security features.

    • Watermarks — FFT-based frequency analysis for subtle patterns
    • Hologram regions — HSV saturation analysis for iridescent regions
    • Microprint — Edge density analysis in expected microprint zones
    • Document structure — Layout conformity validation

    A document is considered to have security features if ≥ 2 of 4 checks pass.

    4.7 AML Screening (aml_screening.py)¶

    What it does: Fuzzy name matching against the OpenSanctions consolidated dataset.

    Data source: https://data.opensanctions.org/datasets/latest/default/entities.ftm.json - Downloaded to data/sanctions/entities.ftm.json - Parsed into in-memory entity index (singleton pattern)

    Matching algorithm: - Unicode normalization (NFKD, strip diacritics) - Token-set overlap scoring - Levenshtein distance (pure Python implementation, no external deps) - Configurable match threshold

    Entity types screened: Persons, organizations — covers sanctions, PEPs, and crime watchlists.

    4.8 NFC Verification (nfc_verification.py)¶

    What it does: Parses ICAO 9303 e-Passport NFC chip data.

    Supported Data Groups: - DG1 — MRZ data (TLV parsing → tag 0x5F1F, then MRZ validation with check digits) - DG2 — Face biometric (CBEFF container → JPEG/JP2 extraction) - SOD — Security Object Document (ASN.1 structure validation via asn1crypto)

    Cross-verification: Can compare DG2 face against a selfie using the FaceVerificationService.

    Dependencies: asn1crypto

    4.9 Video KYC (video_kyc.py)¶

    What it does: Processes uploaded video for identity verification.

    Pipeline: 1. Create a session → receive session_id 2. Upload video (MP4/WebM/QuickTime, max 50 MB, max 30 seconds) 3. Frame extraction via OpenCV 4. Per-frame analysis: liveness check, face consistency, scene change detection 5. Optional face matching against a reference image

    In-memory sessions with automatic state tracking (created → processing → completed/failed).

    4.10 Workflow Engine (workflow_engine.py)¶

    What it does: Orchestrates ordered sequences of verification steps.

    Step types: ocr, liveness, face_match, fraud_check, age_verify

    Workflow definition: 

    {
  "name": "Standard KYC",
  "steps": [
    {"name": "Extract Document", "type": "ocr", "on_fail": "stop"},
    {"name": "Check Liveness", "type": "liveness", "on_fail": "stop"},
    {"name": "Match Face", "type": "face_match", "on_fail": "stop"},
    {"name": "Fraud Analysis", "type": "fraud_check", "on_fail": "continue"}
  ]
}

    Failure handling: Each step can be configured with on_fail: stop (abort workflow), skip (proceed to next), or continue (proceed but flag).

    Execution tracking: Each execution gets a unique ID with per-step status, duration, and results.

    4.11 Analytics (analytics_service.py)¶

    What it does: In-memory event tracking with a 10,000-event ring buffer.

    Time windows: 1h, 24h, 7d, 30d

    Tracked metrics: - Event counts by type - Verification pass/fail rates - Fraud detection counts - Latency percentiles (when duration_ms is provided)

    4.12 Webhooks (webhook_service.py)¶

    What it does: Registers callback URLs and delivers event payloads with HMAC-SHA256 signatures.

    • Register webhooks for specific event types
    • Automatic retry (3 attempts with exponential backoff)
    • Payload signing: HMAC-SHA256(payload, secret) in the X-Webhook-Signature header
    • In-memory registry (POC — not persistent)

    4.13 Device Fingerprint (device_fingerprint.py)¶

    What it does: Extracts risk signals from HTTP request headers.

    Signals detected: - Emulator (BlueStacks, Nox, Genymotion, etc.) - Bot/automation (Selenium, Puppeteer, Playwright, curl) - Headless browser markers - Datacenter IP ranges (AWS, GCP, Azure CIDRs) - User-Agent anomalies

    Output: Risk score (0–100) with flags and recommendation (allow, challenge, deny).

    4.14 Geo Risk (geo_risk.py)¶

    What it does: IP geolocation risk assessment using ip-api.com (free tier, 45 req/min).

    Signals: - Proxy/VPN detection (weight: 30) - Hosting/datacenter IP (weight: 25) - Country mismatch against expected nationality (weight: 35) - High-risk country list (configurable, weight: 10)

    Caching: In-memory, 1-hour TTL per IP.

    4.15 Consent Management (consent_service.py)¶

    What it does: TTL-based consent records with revocation support.

    Consent purposes: identity_verification, biometric_processing, data_storage

    Lifecycle: Grant → validate → revoke. Records expire automatically based on duration_hours. Revocation triggers registered purge callbacks.

    4.16 Batch Processing (batch_service.py)¶

    What it does: Async job queue for processing up to 20 documents concurrently.

    • ThreadPoolExecutor with 4 workers
    • Job TTL: 1 hour (auto-cleanup)
    • Poll-based status tracking: pending → processing → completed/failed
    • Each document runs OCR + fraud detection independently

    4.17 Age Estimation (age_estimation.py)¶

    What it does: Estimates age from face images using InsightFace's built-in age attribute.

    • Reuses the same buffalo_l model instance as FaceVerificationService (no duplicate loading)
    • verify_age() — Compares estimated age against a provided date of birth (±5 year tolerance)

    4.18 PAD Conformance (pad_conformance.py)¶

    What it does: Maps liveness scores to ISO 30107-3 PAD levels.

    Liveness Score PAD Level APCER Estimate BPCER Estimate
    ≥ 0.85 Level 3 1% 15%
    ≥ 0.60 Level 2 5% 10%
    ≥ 0.30 Level 1 20% 5%
    < 0.30 None 100% 0%

    Attack classification: Print, replay (screen), mask, deepfake — based on per-layer score decomposition.

    5. ML Models¶

    Model Inventory¶

    Model Format Size Purpose Download Source
    InsightFace buffalo_l ONNX (multiple) ~300 MB Face detection, recognition, age, gender InsightFace model zoo
    anti-spoof-mn3 ONNX ~12 MB Anti-spoofing (MobileNetV3) OpenVINO Model Zoo

    MediaPipe Face Landmarker TFLite task ~5 MB 478-point 3D face landmarks Google MediaPipe

    Auto-Download Behavior¶

    All models are downloaded automatically on first startup:

    • InsightFace downloads to ~/.insightface/models/buffalo_l/
    • anti-spoof-mn3 and deepfake-vit-b16 download to the project's models/ directory
    • MediaPipe and PaddleOCR models are managed by their respective libraries

    GPU vs CPU Execution¶

    By default, all ONNX models use CPUExecutionProvider. To enable GPU:

    1. Install CUDA-compatible ONNX Runtime: 

      pip install onnxruntime-gpu

    2. The services will automatically use CUDAExecutionProvider if available. To verify: 

      curl http://localhost:8080/debug/gpu

    The /debug/gpu endpoint reports: - PyTorch CUDA availability - ONNX Runtime available providers - PaddlePaddle GPU status - InsightFace active providers

    Model Directory¶

    models/
├── anti-spoof-mn3.onnx        # Anti-spoofing model
└── deepfake-vit-b16.onnx      # Deepfake detection model

    InsightFace models are stored separately in ~/.insightface/models/buffalo_l/.

    6. API Versioning & Rate Limiting¶

    API Versioning¶

    Strategy: Both v1 and v2 are mounted from the same routers, allowing future divergence.

    /api/v1/*  ← Current stable API
/api/v2/*  ← Future version (currently identical to v1)

    Accept-Version Header: - Clients can send Accept-Version: v1 or Accept-Version: v2 - Default: v1 - Invalid values fall back to v1

    Response Headers: | Header | Description | |---|---| | API-Version | The version that handled the request | | Deprecation | true if the endpoint is deprecated | | Sunset | Date when a deprecated endpoint will be removed | | Link | Successor endpoint URL (for deprecated endpoints) |

    Configuring Deprecations:

    In app/middleware/versioning.py, add entries to DEPRECATED_ENDPOINTS:

    DEPRECATED_ENDPOINTS = {
    "/api/v1/old-endpoint": {
        "date": "2026-06-01",
        "successor": "/api/v2/new-endpoint"
    },
}

    Rate Limiting¶

    Powered by SlowAPI (built on limits library).

    Tier Limit Applies To
    Default 60 requests/minute All endpoints
    Heavy 10 requests/minute Liveness, batch, face verification

    Rate limit headers (on every response): - X-RateLimit-Limit - X-RateLimit-Remaining - X-RateLimit-Reset

    429 Response: 

    {
  "error": "Rate limit exceeded",
  "detail": "10 per 1 minute",
  "retry_after": 60
}

    Rate limits are keyed by client IP (get_remote_address).

    7. Security Considerations¶

    Stateless Processing¶

    This POC processes images in-memory and returns results immediately. No images or biometric data are written to disk during normal operation (except temporary files for video processing, which are deleted after use).

    In-Memory Only (POC Limitation)¶

    All state (face database, webhooks, consent records, analytics, batch jobs, workflow definitions) is stored in Python data structures and lost on restart. For production:

    Component Production Alternative
    Face database PostgreSQL + pgvector, or Milvus/Pinecone
    Webhooks PostgreSQL + message queue (RabbitMQ, SQS)
    Consent records PostgreSQL with audit logging
    Analytics ClickHouse, TimescaleDB, or cloud analytics
    Batch jobs Celery + Redis, or cloud job queues
    AML data Dedicated compliance platform

    TLS¶

    The application serves HTTP. Always deploy behind a TLS-terminating reverse proxy (nginx, Caddy, cloud load balancer) in production.

    Consent Management¶

    The consent service provides a framework for recording user consent before biometric processing. In production, integrate with your legal/compliance infrastructure and ensure GDPR/data protection compliance.

    PII Handling¶

    • OCR results contain PII (names, dates, document numbers)
    • Face embeddings are biometric data
    • Ensure proper data handling policies in production
    • Consider encryption at rest and in transit

    For GPU acceleration:

    9. Integration Guide¶

    Quick Start: Verify an Identity in 3 API Calls¶

    # Step 1: Extract document data
curl -X POST http://localhost:8080/api/v1/ocr-document \
  -F "front_image=@id_card.jpg" \
  | jq '.extracted_data'

# Step 2: Check liveness of the selfie
curl -X POST http://localhost:8080/api/v1/liveness-check \
  -F "image=@selfie.jpg" \
  | jq '{is_live: .is_live, score: .overall_score}'

# Step 3: Match document photo against selfie
curl -X POST http://localhost:8080/api/v1/verify-face \
  -F "passport_image=@id_card.jpg" \
  -F "live_image=@selfie.jpg" \
  | jq '{match: .match, score: .score}'

    Full Workflow: OCR → Liveness → Face Match → Fraud Check¶

    import requests

BASE = "http://localhost:8080/api/v1"

# 1. OCR
with open("passport.jpg", "rb") as f:
    ocr = requests.post(f"{BASE}/ocr-document", files={"front_image": f}).json()
print(f"Name: {ocr.get('extracted_data', {}).get('full_name')}")

# 2. Liveness
with open("selfie.jpg", "rb") as f:
    live = requests.post(f"{BASE}/liveness-check", files={"image": f}).json()
print(f"Live: {live['is_live']} (score: {live['overall_score']})")

# 3. Face match
with open("passport.jpg", "rb") as doc, open("selfie.jpg", "rb") as selfie:
    match = requests.post(f"{BASE}/verify-face",
        files={"passport_image": doc, "live_image": selfie}).json()
print(f"Match: {match['match']} (score: {match['score']})")

# 4. Fraud check
with open("passport.jpg", "rb") as f:
    fraud = requests.post(f"{BASE}/detect-fraud", files={"image": f}).json()
print(f"Fraudulent: {fraud['is_fraudulent']} (score: {fraud['overall_score']})")

    Using the Workflow Engine¶

    import requests

BASE = "http://localhost:8080/api/v1"

# Create a workflow definition
workflow = requests.post(f"{BASE}/workflows", json={
    "name": "Standard KYC",
    "steps": [
        {"name": "OCR", "type": "ocr", "on_fail": "stop"},
        {"name": "Liveness", "type": "liveness", "on_fail": "stop"},
        {"name": "Face Match", "type": "face_match", "on_fail": "stop"},
        {"name": "Fraud Check", "type": "fraud_check", "on_fail": "continue"},
    ]
}).json()

workflow_id = workflow["id"]

# Execute with images
with open("document.jpg", "rb") as doc, open("selfie.jpg", "rb") as selfie:
    execution = requests.post(f"{BASE}/workflows/{workflow_id}/execute",
        files={"document_image": doc, "selfie_image": selfie}).json()

print(execution)

    10. Troubleshooting¶

    Common Errors¶

    Error Cause Solution
    No face detected in image Image too dark, face too small, or no face present Ensure face is well-lit and occupies >10% of the image
    PaddleOCR init failed PaddlePaddle installation issue pip install paddlepaddle==3.1.1 paddleocr[all]>=3.4.0
    passporteye import error scikit-image version mismatch Use scikit-image>=0.19.0,<0.21.0
    429 Rate limit exceeded Too many requests Wait for Retry-After seconds or reduce request rate
    Session not found (Video KYC) Session expired or invalid ID Create a new session; sessions are in-memory only

    Model Download Issues¶

    • Slow downloads: Models are large (343 MB for deepfake). First startup may take several minutes.
    • Network errors: If download fails mid-way, delete the partial file from models/ and restart.
    • Proxy/firewall: Ensure access to:
    • https://storage.openvinotoolkit.org (anti-spoof model)
    • https://huggingface.co (deepfake model)
    • https://github.com/deepinsight/insightface (InsightFace models)

    Memory Requirements¶

    Configuration RAM
    Minimum (all models loaded) ~2 GB
    Recommended 4 GB
    With large AML dataset loaded 4–6 GB
    Batch processing (20 docs) 4–8 GB

    numpy / OpenCV Version Conflicts¶

    The project pins numpy>=1.24.0,<2.0.0 to avoid breaking changes in numpy 2.x. If you see:

    AttributeError: module 'numpy' has no attribute 'float'

    Ensure numpy < 2.0: 

    pip install "numpy>=1.24.0,<2.0.0"

    skimage.transform.rescale multichannel Error¶

    PassportEye uses a deprecated multichannel parameter. The app monkey-patches this in passport_ocr.py. If you still see errors, ensure scikit-image<0.21.0.

    HEIC Image Support¶

    HEIC/HEIF images are supported if pillow-heif is installed. The app registers the HEIF opener at startup. Without it, HEIC uploads will fail.
