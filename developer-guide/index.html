    Developer Guide¶

    This guide covers everything you need to integrate Cloud Bhutan eKYC into your application.

    Getting Started¶

    Base URL¶

    https://your-ekyc-instance.com/api/v1/

    Authentication¶

    Contact Cloud Bhutan to obtain your API credentials. Include your API key in requests:

    curl -H "Authorization: Bearer YOUR_API_KEY" \
  https://your-ekyc-instance.com/api/v1/health

    Supported Formats¶

    • Images: JPEG, PNG
    • Max file size: 10MB per image
    • Video (Video KYC): MP4, WebM — max 30 seconds, 50MB

    Rate Limits¶

    Tier Limit Endpoints
    Standard 60 requests/min Most endpoints
    Heavy 10 requests/min Liveness, batch, verify-face

    Rate limit headers are included in every response: - X-RateLimit-Limit — Max requests allowed - X-RateLimit-Remaining — Remaining requests - X-RateLimit-Reset — Reset timestamp

    API Versioning¶

    The API supports versioning via URL prefix and header:

    • URL: /api/v1/ (current), /api/v2/ (latest)
    • Header: Accept-Version: v1 or Accept-Version: v2

    Both versions are currently identical. When breaking changes are introduced, v1 will be maintained with deprecation notices.

    Deprecation is signalled via response headers: - Deprecation: true - Sunset: <date> - Link: <new-url>; rel="successor-version"

    Quick Integration¶

    Verify an Identity in 3 Steps¶

    Step 1 — Extract document data (OCR)

    curl -X POST /api/v1/ocr-document \
  -F "front_image=@id_card_front.jpg" \
  -F "back_image=@id_card_back.jpg"

    Response includes extracted fields: name, date of birth, document number, expiry, nationality, and more.

    Step 2 — Verify the person is real (Liveness)

    curl -X POST /api/v1/liveness-check \
  -F "image=@selfie.jpg"

    Returns a liveness score with ISO 30107 PAD conformance level. A score above 0.5 indicates a live person.

    Step 3 — Match faces (Verification)

    curl -X POST /api/v1/verify-face \
  -F "passport_image=@id_card_front.jpg" \
  -F "live_image=@selfie.jpg"

    Returns a similarity score. A score above 0.6 indicates a match (configurable threshold).

    Verification Workflows¶

    For production use, we recommend using the Workflow Engine to chain multiple verification steps into a single automated pipeline.

    Create a Workflow¶

    curl -X POST /api/v1/workflows \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Full KYC Verification",
    "steps": [
      {"name": "ocr", "type": "ocr", "config": {}, "on_fail": "stop"},
      {"name": "liveness", "type": "liveness", "config": {"threshold": 0.5}, "on_fail": "stop"},
      {"name": "face_match", "type": "face_match", "config": {"threshold": 0.6}, "on_fail": "stop"},
      {"name": "fraud_check", "type": "fraud_check", "config": {}, "on_fail": "continue"}
    ]
  }'

    Execute a Workflow¶

    curl -X POST /api/v1/workflows/{workflow_id}/execute \
  -F "images=@id_front.jpg" \
  -F "images=@selfie.jpg" \
  -F 'metadata={"document_type": "passport"}'

    Returns results for each step with overall pass/fail status.

    Webhook Integration¶

    Receive real-time notifications when async operations complete.

    Register a Webhook¶

    curl -X POST /api/v1/webhooks \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://your-app.com/webhook/ekyc",
    "events": ["batch.completed", "batch.failed"],
    "secret": "your-webhook-secret"
  }'

    Webhook Payload¶

    {
  "event": "batch.completed",
  "job_id": "abc-123",
  "status": "completed",
  "summary": { "total": 20, "passed": 18, "failed": 2 },
  "timestamp": "2026-03-12T10:00:00Z"
}

    Payloads are signed with HMAC-SHA256. Verify using the X-Webhook-Signature header and your secret.

    Batch Processing¶

    Process multiple documents in a single request (up to 20 documents).

    # Submit batch
curl -X POST /api/v1/batch/verify \
  -F "images=@doc1.jpg" \
  -F "images=@doc2.jpg" \
  -F "images=@doc3.jpg"

# Check status
curl /api/v1/batch/{job_id}

# Get results
curl /api/v1/batch/{job_id}/results

    Jobs expire after 1 hour. Use webhooks for real-time completion notifications.

    AML / Sanctions Screening¶

    Screen individuals against international sanctions lists and PEP databases.

    curl -X POST /api/v1/aml/screen \
  -F "full_name=John Doe" \
  -F "date_of_birth=1985-06-15" \
  -F "nationality=US"

    Returns matches with risk level: clear, potential_match, or confirmed_match.

    NFC Chip Verification¶

    For e-Passports with NFC chips, verify cryptographic authenticity of chip data.

    curl -X POST /api/v1/nfc/verify-chip \
  -F 'chip_data={"dg1": "<base64>", "dg2": "<base64>", "sod": "<base64>"}' \
  -F "document_image=@passport.jpg"

    The mobile SDK handles NFC reading — the API receives and validates the extracted chip data.

    Video KYC¶

    For higher-assurance verification, use recorded video submissions.

    # Create session
curl -X POST /api/v1/video-kyc/session

# Upload video + reference photo
curl -X POST /api/v1/video-kyc/{session_id}/upload \
  -F "video=@recording.mp4" \
  -F "reference_image=@id_photo.jpg"

# Get results
curl /api/v1/video-kyc/{session_id}/results

    The system extracts frames, performs liveness analysis, checks face consistency, and detects scene splicing.

    Risk Assessment¶

    Assess device and network risk to flag suspicious submissions.

    # Device fingerprinting
curl -X POST /api/v1/device-risk \
  -H "Content-Type: application/json" \
  -d '{"screen_resolution": "1920x1080", "timezone": "Asia/Thimphu"}'

# IP risk check
curl -X POST /api/v1/ip-risk \
  -F "document_country=BT"

# Combined assessment
curl -X POST /api/v1/combined-risk \
  -F "document_country=BT"

    Returns a risk score (0–100) with flags and a recommendation: allow, review, or block.

    Consent Management¶

    Track user consent for GDPR/privacy compliance.

    # Record consent before verification
curl -X POST /api/v1/consent \
  -H "Content-Type: application/json" \
  -d '{
    "subject_id": "user-123",
    "purpose": "identity_verification",
    "scope": "biometric_processing",
    "duration_hours": 24
  }'

# Check consent status
curl /api/v1/consent/{consent_id}

# Withdraw consent
curl -X DELETE /api/v1/consent/{consent_id}

    Analytics¶

    Monitor verification performance and trends.

    # Overall dashboard
curl /api/v1/analytics/summary?window=24h

# Verification breakdown
curl /api/v1/analytics/verifications?window=7d

# Fraud detection stats
curl /api/v1/analytics/fraud?window=30d

# Performance metrics
curl /api/v1/analytics/performance?window=24h

    Available time windows: 1h, 24h, 7d, 30d.

    Error Handling¶

    All errors follow a consistent format:

    {
  "detail": "Description of the error"
}
    Status Code Meaning
    400 Bad request — invalid parameters or image format
    404 Resource not found
    413 File too large
    422 Validation error — check field requirements
    429 Rate limit exceeded — check Retry-After header
    500 Internal server error
